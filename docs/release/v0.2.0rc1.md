Bolorgir 0.2.0rc1 is a **public preview** of 0.2.0: an embeddable structured-generation engine for LLMs (a Zig core with a versioned C ABI, Python bindings and a Hugging Face Transformers adapter). Given a JSON Schema or a set of literal strings, it computes the allowed next tokens at every generation step. This is a GitHub pre-release; nothing is uploaded to PyPI.

## Status

- `canonical-v1` is the default profile (a frozen subset). `spec-v1` is **experimental**; select it with `profile="spec-v1"`.
- The core library of this preview passed the T3 coverage acceptance and its R6 review: verdict **admitted** for core sha256 `6e62e0d1526c6e5369457d2f7205675b7cb163e3374b96d8cb5115c28873e914` ([acceptance.md](https://github.com/wpartscom/bolorgir/blob/v0.2.0rc1/benchmarks/coverage/spec-v1/t3-6e62e0d1/review-3/acceptance.md)).
- The full T8a run (MaskBench, `spec-v1`, Llama 3.1 tokenizer, 900 s per file) is **not complete**. The stable 0.2.0 release needs it; this preview does not.
- Some `spec-v1` schemas are slow, end in `RESOURCE_LIMIT`, or run for a long time. With a 128k-token vocabulary a single mask can take about a second and a file of a few documents can exceed 900 s; for one MaskBench schema (`Github_easy---o89710`) the first mask did not return within 120 s, and with a byte-level vocabulary it ends in `RESOURCE_LIMIT`.
- Memory limits (`memory_limit_mb` and the other budgets) bound memory, not the time of a call. Use your own deadline with `work_limit_ops` or a `CancelToken`; how quickly they stop the slow cases above was not measured for this preview.
- Performance figures in the README are historical (engine 0.1.0 and the code before it, profile `canonical-v1`) and were not re-measured for this preview.

## Install

```sh
python3 -m venv .venv && . .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install https://github.com/wpartscom/bolorgir/releases/download/v0.2.0rc1/bolorgir-0.2.0rc1-cp310-abi3-manylinux_2_28_x86_64.whl
```

The wheel is `cp310-abi3-manylinux_2_28_x86_64`: one file for CPython 3.10 to 3.13 on Linux x86_64 with glibc 2.28 or newer. `SHA256SUMS` below lists the sums of the wheel and the sdist; the sdist bundles the same core and builds with a C compiler, without Zig. The README of the tag shows how to check the sums, how to build from the tag (`git clone --branch v0.2.0rc1`, Zig 0.15.2) and a quickstart that needs no model download: [README](https://github.com/wpartscom/bolorgir/blob/v0.2.0rc1/README.md#install).

## Platforms

- Linux x86_64, glibc 2.28 or newer (manylinux_2_28).
- CPython 3.10, 3.11, 3.12 and 3.13; the release workflow installs the wheel in a clean `python:3.x-slim` container for each of them and runs the smoke test and the quickstart.

macOS, Windows and Linux aarch64 are not built or tested.

## Changes since 0.1.0

- `spec-v1`: conjunctions of numeric keywords (`minimum`/`maximum`, `multipleOf`, `integer`, excluded constants) are certified in closed form ([ADR-0011](https://github.com/wpartscom/bolorgir/blob/v0.2.0rc1/docs/adr/ADR-0011-numeric-conjunction.md)); `{"type":"integer","minimum":0,"maximum":1}` and the other schemas of the audit no longer fail with `RESOURCE_LIMIT`.
- `spec-v1`: more completion certificates settle states that previously ended in `RESOURCE_LIMIT` (keys in the middle of an escape, `oneOf` votes, `if`/`then`/`else`, `dependentRequired`).
- `spec-v1`: the completion certificates of open objects are exact for `patternProperties` keys, dependencies (`dependentRequired`) and `maxProperties`. A mask no longer admits a key, a closing quote or a comma after which the object cannot be completed.
- Fixes found by the new generative tests: a `fill_mask` abort, value verdicts of `oneOf`, a parser spawn defect, the `minProperties` emptiness of closed objects and the parser thread cap.
- The memory a compile is charged no longer depends on what the process ran before.
- Compile-time generatability probe (`probe="probe"` or `"strict"`, [ADR-0012](https://github.com/wpartscom/bolorgir/blob/v0.2.0rc1/docs/adr/ADR-0012-generatability-probe.md)) and `on_constraint_error="fail_row"` in the Transformers adapter.
- `bolorgir.serializer` emits keys in an order consistent with both an outer object and its `oneOf`/`anyOf` branches.

The full list is in [CHANGELOG.md](https://github.com/wpartscom/bolorgir/blob/v0.2.0rc1/CHANGELOG.md), section 0.2.0.

## Limitations

- Output is compact JSON with object keys in schema declaration order.
- Standalone regular expressions and arbitrary grammars are not supported.
- Tokenizers: byte-level BPE and SentencePiece with byte fallback; other decoder chains are refused with `UNSUPPORTED_TOKENIZER`.
- No vLLM or SGLang integration.

## Reporting a problem

Open an [issue](https://github.com/wpartscom/bolorgir/issues/new?template=bug_report.yml) with the version and how it was installed, the platform (OS, CPU architecture, glibc, Python), the schema and profile, the tokenizer (name and revision, or how the `TokenizerBundle` was built), a minimal script that reproduces it, and the observed result (exception or status with its message, generated text, or how long a call ran). Vulnerabilities: [SECURITY.md](https://github.com/wpartscom/bolorgir/blob/v0.2.0rc1/SECURITY.md).
