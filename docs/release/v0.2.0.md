Bolorgir 0.2.0 publishes the engine on PyPI with the correctness fixes of the external audit for the experimental `spec-v1` profile. The default profile of the API stays `canonical-v1`. Slow masks and `RESOURCE_LIMIT` on some `spec-v1` schemas remain; see Limitations.

## Install

```sh
python3 -m pip install --upgrade pip
python3 -m pip install bolorgir                  # core, C extension, tokenizer bridge
python3 -m pip install "bolorgir[transformers]"  # with the Hugging Face adapter
```

The wheel is `cp312-abi3-manylinux_2_28_x86_64`: one wheel for CPython 3.12 to 3.15 on Linux x86_64 with glibc 2.28 or newer. The sdist bundles the same core library and needs a C compiler, not Zig. Building from source is described in the README section Install.

## Platforms

- Linux x86_64, glibc 2.28 or newer (manylinux_2_28).
- CPython 3.12, 3.13, 3.14 and 3.15; each is checked by installing the published wheel in a clean `python:3.x-slim` container.

macOS, Windows and Linux aarch64 are not built or tested in this release.

## Changes since 0.1.0

- Toolchain and Python range: the core is built with Zig 0.17.0, and the
  wheel is `cp312-abi3` for CPython 3.12-3.15. CPython 3.10 (EOL in
  October 2026) and 3.11 are dropped; Python 3.15 is supported on regular
  GIL builds only (free-threaded 3.15t is not claimed).
- `spec-v1`: conjunctions of numeric keywords (`minimum`/`maximum`, `multipleOf`, `integer`, excluded constants) are certified in closed form ([ADR-0011](https://github.com/wpartscom/bolorgir/blob/main/docs/adr/ADR-0011-numeric-conjunction.md)); `{"type":"integer","minimum":0,"maximum":1}` and the other schemas of the audit no longer fail with `RESOURCE_LIMIT`.
- `spec-v1`: more completion certificates settle states that previously ended in `RESOURCE_LIMIT` (keys in the middle of an escape, `oneOf` votes, `if`/`then`/`else`, `dependentRequired`).
- `spec-v1`: the completion certificates of open objects are exact for `patternProperties` keys, dependencies (`dependentRequired`) and `maxProperties`. A mask no longer admits a key, a closing quote or a comma after which the object cannot be completed; the acceptance run of the first candidate had ended such documents in `DEAD_END`, and an object at its `maxProperties` cap could still take a comma.
- Fixes found by the new generative tests: a `fill_mask` abort, value verdicts of `oneOf`, a parser spawn defect, the `minProperties` emptiness of closed objects and the parser thread cap.
- The memory a compile is charged no longer depends on what the process ran before.
- Compile-time generatability probe (`probe="probe"` or `"strict"`, [ADR-0012](https://github.com/wpartscom/bolorgir/blob/main/docs/adr/ADR-0012-generatability-probe.md)) and `on_constraint_error="fail_row"` in the Transformers adapter.
- `bolorgir.serializer` emits keys in an order consistent with both an outer object and its `oneOf`/`anyOf` branches.

## Limitations

- `spec-v1` is experimental. A compiled schema can still fail `fill_mask` or `accept_token` with `RESOURCE_LIMIT` when completion reachability cannot be proven within the search budget; a token is never admitted without a proof. `fail_row` and the probe handle it.
- Some `spec-v1` masks are slow (about a second per mask on some schemas with a 128k-token vocabulary). Memory limits bound memory, not the time of a call; use a deadline with `work_limit_ops` or a `CancelToken`.
- Output is compact JSON with object keys in schema declaration order.
- Standalone regular expressions and arbitrary grammars are not supported.
- Tokenizers: byte-level BPE and SentencePiece with byte fallback; other decoder chains are refused with `UNSUPPORTED_TOKENIZER`.
- No vLLM or SGLang integration in this release.

The full list is in the README section [Schema profiles and limitations](https://github.com/wpartscom/bolorgir#schema-profiles-and-limitations).
