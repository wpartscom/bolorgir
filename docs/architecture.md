# architecture.md — архитектура zig-constraints (MVP)

Дополняет ТЗ §6, docs/DESIGN.md и docs/API.md. Описывает модули, их границы и
модели данных/памяти/потоков. Точные сигнатуры — в docs/API.md и
include/zig_constraints.h; семантика языка — в docs/semantics.md.

## 1. Общая схема (ТЗ §6)

~~~mermaid
flowchart TD
    A[Схема и профиль] --> C[Компилятор ограничений]
    B[Адаптер токенизатора] --> T[Общее представление токенов]
    C --> G[Неизменяемая грамматика]
    G --> S[Состояние сессии]
    T --> M[Построитель маски]
    S --> M
    K[Ограниченный кэш] <--> M
    M --> P[Перенос и применение маски]
    F[Forward модели на GPU] --> P
    P --> Q[Sampling на устройстве модели]
    Q --> U[Принятие token ID]
    U --> S
~~~

Блоки C, G, S, T, M, K — ядро (CPU). Блоки F, Q — модель и sampling (устройство
модели). Блок P — адаптер интеграции (Python/Transformers), вне ядра.

## 2. Модули ядра

| Модуль | Файл | Ответственность |
|---|---|---|
| JSON-парсер схемы | `src/json.zig` | Разбор входного JSON в дерево значений; отказ при дубликатах ключей (INVALID_SCHEMA); лимит размера схемы. |
| Компилятор схем | `src/schema.zig` | Проверка профиля FR-1 (таблица supported_features.md §1), раскрытие `$defs`/`$ref` с контролем ацикличности, нормализация enum/const (точная десятичная, semantics.md §6), построение IR. Ошибки схемы — до первого forward-прохода. |
| Компилятор FR-3 | `src/literals.zig` | Список буквальных строк → choice из raw-literal узлов; дедупликация; пустая строка — мгновенно завершённый литерал. |
| IR грамматики | `src/grammar.zig` | Неизменяемые узлы literal / str / int_v / num_v / choice / seq / repeat / object; арена внутри Grammar; identity — два независимых 64-битных хэша исходных байт схемы + kind (FNV-1a `id` + Wyhash `id_hi`). Повторения — счётчики, без разворачивания maxItems. |
| Парсер | `src/parser.zig` | Инкрементный разбор: `State` — ограниченный набор threads (NFA-симуляция, ADR-0001), каждый thread — стек POD-frames ёмкостью max_depth. `feedBytes` посимвольно; ошибка thread'а — отбрасывание; превышение max_threads — RESOURCE_LIMIT. `canEnd`, `hashState`, `eqlStates`. |
| Построитель маски | `src/mask.zig` | Обнуление out; EOS-биты по canEnd; обычные токены — итеративный DFS по trie словаря (ребро = байт в feedBytes, Parse отсекает поддерево, терминал выставляет биты цепочки id); special non-EOS пропускаются; пустая маска — DeadEnd. Шаги обхода взимаются в бюджет работы/отмену (work.zig). Повторный вызов на том же состоянии — побитово тот же результат. |
| Токенизатор | `src/tokenizer.zig` | Копирование таблицы во владение контекста; валидация покрытия id, eos/special; identity = FNV-1a-64 (тег адаптера, байты токенов, eos, special, vocab_size); плоское префиксное дерево словаря (trie) для обхода маской; совпадающие байтовые образы — цепочка id. |
| Покрытие токенизатора | `src/coverage.zig` | Проверка на `zg_compile`: литералы сегментируются в токены словаря, открытые классы и структурный синтаксис имеют порождаемое завершение; иначе — UNSUPPORTED_TOKENIZER. Консервативно (границы токенов = границы узлов); byte-полный словарь проходит всегда. |
| Бюджет работы и отмена | `src/work.zig` | Per-call `Work`: счётчик ops против `work_limit_ops` (0 = без лимита) + чтение вызывательского флага отмены (acquire); Cancelled/ResourceLimit из циклов compile/маски/coverage/precompute. |
| Прогрев precompute | `src/precompute.zig` | Экспериментальный BFS по достижимым состояниям при `zg_compile` с вычислением масок в кэш, до `precompute_max_states`; исчерпание бюджетов — тихая деградация в lazy, наружу только Cancelled. |
| Учитывающий аллокатор | `src/alloc.zig` | `Accounting` над std.mem.Allocator: used/peak по категориям {tokenizer, grammar, session, cache, temp} + total; лимит total → отказ выделения → RESOURCE_LIMIT; `SessionAccount` с лимитом сессии. После destroy контекста used == 0 (проверяется тестами). |
| Статистика | `src/stats.zig` | Таймеры compile/tokenizer_prepare/accept/mask (ns), счётчики кэша, память из Accounting, tokens_accepted, счётчики ошибок по классам, cache_adaptive_skips, precompute_states, work_ops_total — поля зеркалят `zg_stats`. |
| Кэш LRU | `src/cache.zig` | Ключ {grammar_id, grammar_hi, tokenizer_id, state_hash} (identity грамматики 128 бит); значение — копия состояния (проверка коллизий через eqlStates) + копия маски. Жёсткий байтовый бюджет через ограничивающий allocator (включая Entry и HashMap); вытеснение LRU-хвоста; budget==0 — выключен (lazy-эквивалент). Admission (adaptive): put при seen >= adaptive_min_hits ИЛИ compute_ns >= adaptive_min_cost_ns. Никогда не меняет содержимое маски. |
| C ABI | `src/c_api.zig`, `src/root.zig` | Экспорт функций `zg_*`; владение: контекст > грамматики (refcount) > сессии; destroy занятого контекста — BUSY; маппинг ошибок Zig → zg_status; непредвиденное — INTERNAL + сессия aborted. |

### Python-мост и адаптер (вне ядра)

- `python/` — CPython C-расширение `zig_constraints._core` на Limited API
  (abi3), линкуется с libzig_constraints.so (rpath $ORIGIN). GIL освобождается
  на время нативных вызовов; одна сессия сериализует свои операции; ошибки ABI
  → типизированные исключения (по классу на zg_status).
- `zig_constraints.transformers` (extra; torch импортируется только внутри) —
  LogitsProcessor + `constrained_generate`: greedy/sampling, фиксированный
  батч, left padding, финальный accept последних токенов, completed/stop_reason
  по строкам (completed=True только при принятом разрешённом EOS; без EOS —
  "length"). Неподдерживаемые режимы по эффективному generation_config
  (num_beams > 1 и т.п.) — UnsupportedModeError до генерации. Глобальный
  monkey-patch не используется.

## 3. Граница CPU/GPU

- Ядро получает ограничения, токены и состояние; возвращает маску (массив
  uint32, ceil(vocab_size/32) слов) в буфер вызывающей стороны. Матрица логитов
  не передаётся с GPU на CPU ради работы движка.
- Для GPU-модели маска переносится на устройство логитов и применяется
  адаптером (в MVP — обычные операции PyTorch; собственные CUDA/Triton-ядра не
  обязательны). Распаковка, перенос, синхронизация и применение входят в
  интеграционные измерения (B7).
- Для CPU-модели маска применяется на CPU; CPU-маска не означает zero-copy для
  GPU.
- Ограничения применяются до top-k/top-p; последующие операции не могут
  повторно разрешить запрещённый token ID (FR-15).

## 4. Потоковая модель

- MVP — последовательное исполнение: один вызов ABI обрабатывается в потоке
  вызывающей стороны; `zg_fill_masks_batch` идёт по сессиям последовательно,
  статус каждой строки независим.
- Внутреннего пула потоков нет; новые потоки на каждом токене не создаются.
  Пул потоков — оптимизация после профилирования (результат не должен зависеть
  от числа потоков).
- Независимые сессии допускают параллельные вызовы снаружи; одновременное
  изменение одной сессии запрещено контрактом и блокируется Python-обвязкой.
- Состояния сессии не разделяются между потоками; разделяемые данные
  (грамматика, таблица токенизатора) неизменяемы после создания.

## 5. Модель памяти и лимиты

- Все выделения ядра проходят через `Accounting` с категориями; резервируемая
  память учитывается. Общий лимит включает временные данные компиляции и все
  живые объекты контекста.
- Грамматика — арена, неизменяема, разделяется сессиями через refcount; одна
  схема не копируется на каждую сессию.
- Состояние сессии — inline-массивы фиксированной ёмкости (threads × frames),
  полный текст неограниченной строки не накапливается; незавершённый лексический
  элемент и UTF-8-автомат — в рамках thread'а.
- Лимиты по умолчанию: ядро 256 MiB; кэш 64 MiB; сессия 8 MiB; схема 1 MiB;
  глубина 64; threads 64 (supported_features.md §6). При заполнении кэша работа
  продолжается через lazy, если остальные лимиты позволяют.
- Возврат памяти проверяется после destroy: used по всем категориям == 0.
- Межграмматическое переиспользование — только для доказанно эквивалентных
  подструктур; коллизия хэша кэша проверяется сравнением содержимого
  (eqlStates), а не считается совпадением.

## 6. Детерминизм и наблюдаемость

- При одинаковых токенизаторе, профиле, схеме и префиксе все режимы
  (lazy/adaptive/precompute) дают побитово одинаковую маску; вытеснение
  кэша и повторное создание сессии язык не меняют (NFR-1, T2). Прогрев
  precompute только заполняет кэш заранее и результатов не меняет.
- RNG в ядро не входит.
- `zg_get_stats` / `zg_get_stats_session`: время compile/prepare/accept/mask,
  попадания/промахи/вытеснения кэша, учтённая и пиковая память по категориям.
  Подробное логирование выключено по умолчанию; тексты ответов и схем в логи
  автоматически не попадают.
